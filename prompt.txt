  Decisions worth flagging

  - Roles as enum column on users instead of a separate roles table — keeps the schema flat for K8s learning; switch to a join table when you need role-permission granularity.
  - Token blocklist is in-memory in app/auth/blocklist.py — fine for a single replica; for multi-pod swap to Redis (settings.ENABLE_REDIS=True).
  - Notification worker runs in the API process via lifespan — for real K8s learning, move it to its own deployment so you can exercise separate Deployments, probes, and HPA independently.
  - Alembic is configured but you'll need to run alembic upgrade head (the Dockerfile doesn't auto-migrate; the pod should do it on init, e.g. an init-container or a Job).

  Next steps if you want them: a docker-compose.yml with Postgres + the app, Kubernetes manifests (Deployment/Service/Ingress/ConfigMap), or a separate worker Deployment manifest.
